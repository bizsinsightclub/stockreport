# 환각 없는 주식 리포트 — AI와 함께 만든 분석 시스템

> AI 리터러시 클래스 보조자료
> 대상: AI 활용에 관심있는 실무자
> 다루는 사례: KRX 종목 일일 분석 리포터 (`C:\pjt\reporter`)
> 작성일: 2026-05-09

## 0. 이 글이 다루는 것

이 문서는 한 비개발자 출신 실무자가 Claude Code(Anthropic의 CLI 코딩 어시스턴트)와 약 두 단계(Phase 1 + Phase 2)에 걸쳐 만든 **KRX 임의 종목 분석 시스템**의 개발 과정을 정리합니다. 단순한 "AI로 코드 짜본 후기"가 아니라 다음 네 가지를 입체적으로 보여주는 사례로서 가치가 있습니다.

1. **AI 환각(hallucination)을 시스템 차원에서 어떻게 봉쇄하는가** — 프롬프트 잘 쓰기를 넘어, 코드·검증기·데이터 흐름 자체에 환각 방지를 내장한다.
2. **Claude Code와의 단계별 협업 과정** — 한 번의 채팅으로 끝나지 않는, 인계 문서 기반의 다중 세션 협업.
3. **기술 아키텍처 결정의 trade-off** — "왜 정적 HTML인가", "왜 LLM SDK를 자동 호출하지 않는가" 같은 결정 뒤에 깔린 사고.
4. **API 공포증 해결** — 처음 외부 API를 다뤄보는 사람이 어떻게 점진적으로 키·인증·SDK 다루기를 받아들였는가.

읽고 나면, "AI로 코딩한다"의 의미가 단순히 "AI에게 시키면 코드를 뱉어준다"가 아니라 **"AI를 설계 파트너로 삼아 검증 가능한 시스템을 짓는다"** 라는 쪽으로 보일 것입니다.

## 1. 출발점 — 왜 이걸 만들기로 했나

KRX(KOSPI/KOSDAQ) 종목 하나하나에 대해 매일 시세·수급·공시·재무·피어 비교·거시까지 한 페이지로 정리된 리포트를 받고 싶었지만, 시판 서비스는 늘 두 가지 문제를 안고 있었습니다.

- **신뢰할 수 없는 수치**: AI 챗봇에 "삼성전자 어제 종가가 어땠지?"라고 물으면 그럴듯한 숫자를 자신감 있게 답하지만, 실제 KRX 데이터와 일치하지 않는 경우가 잦았습니다. 이른바 *환각(hallucination)*. 투자 의사결정 보조 자료가 잘못된 숫자를 자연어로 자신 있게 설명하면, 그것은 정보가 아니라 위험입니다.
- **API 공포증**: "공식 API 키 받으세요", ".env 파일에 넣으세요", "OAuth 토큰 갱신하세요" — 비개발자에게는 모두 진입장벽입니다. 한 번 헤매면 다시 시도하지 않게 됩니다.

이 두 가지를 동시에 풀어보자는 것이 출발점이었습니다. 즉,

> **환각 없는(no-hallucination)** 분석 리포트를, **API 키 없이도 일단 돌아가는** 형태로, **AI 어시스턴트와 협업해서** 만든다.

이 세 조건이 본 프로젝트의 DNA입니다.

## 2. 무엇을 만드는 시스템인가

```bash
python -m src.main 329180          # HD현대중공업 리포트 발행
python -m src.main 005930          # 삼성전자
python -m src.main 035720 --date 2026-05-09  # 카카오, 특정 날짜로
```

명령 한 줄을 실행하면 다음이 일어납니다.

1. **메타 정보 해석** — ticker(6자리 코드)에서 종목명·시장(KOSPI/KOSDAQ)·업종 코드를 가져옵니다.
2. **피어 자동 선정** — 같은 업종(DART의 KSIC induty_code 매칭)에서 시총 상위 5개 동종 종목을 뽑습니다.
3. **데이터 수집** — 시세·외국인/기관/개인 수급·공시·분기재무·USD/KRW 환율을 외부 API와 라이브러리에서 가져와 *raw JSON 스냅샷*으로 디스크에 보존합니다.
4. **분석** — RSI(14)·MA5/20·MACD 같은 기술지표를 계산하고, 5거래일 누적 수급, 피어 대비 정규화 수익률을 만듭니다.
5. **렌더링** — Plotly 차트와 Jinja2 템플릿으로 정적 HTML 한 페이지를 만듭니다.
6. **검증** — HTML 안에 노출된 모든 숫자가 raw 데이터와 일치하는지, AI가 작성한 코멘트의 모든 numeric claim에 출처가 달려있는지 자동으로 확인하고, 결과 배지를 페이지 하단에 표시합니다.

산출물은 `data/output/{ticker}/{날짜}.html`. 매시간 로컬 Windows 작업 스케줄러가 이 명령을 돌리고, 변경된 HTML만 GitHub Pages 공개 레포(`bizsinsightclub/stockreport`)로 push합니다. 즉, 생성·검증·배포까지 **한 명의 사용자 PC에서 자동으로 매시간 일어나는** 파이프라인입니다.

## 3. 핵심 설계 원칙 — "환각 없는 분석" 3중 안전장치

이 시스템의 존재 이유는 환각 봉쇄입니다. 그래서 데이터가 외부에서 들어와 HTML로 나가기까지, 서로 다른 층위에서 세 가지 안전장치가 작동합니다.

### 3.1 메타 트리플 wrapping — "숫자 옆에 출처가 함께 흐른다"

외부 API에서 가져온 어떤 데이터든, 코드 내부에서는 다음과 같이 4-tuple로 감싸서 다닙니다.

```python
{
  "data":       <원본 응답>,
  "source":    "korea-stock-mcp:get_stock_price",
  "tool_args": {"ticker": "329180", "fromdate": "20260108", "todate": "20260508"},
  "fetched_at": "2026-05-08T07:32:41Z"
}
```

이 dict 그대로 `data/raw/2026-05-08/329180_price.json`에 저장됩니다. **숫자만 따로 떠다니는 일이 없도록** 강제하는 것이 핵심입니다. 이후 어떤 분석·렌더링 단계에서 한 숫자를 보여주려고 해도, 그 숫자가 어느 raw 파일의 어느 path에서 왔는지 추적할 수 있습니다.

이 원칙은 `CLAUDE.md`의 **§3.1**에 박아두었고, 새 데이터 소스를 추가할 때(예: 네이버 컨센서스 스크래핑) 가장 먼저 이 형식으로 반환하도록 강제합니다.

### 3.2 사후 숫자 대조 (`validators/numbers.py`) — "HTML이 거짓말하지 못하게"

HTML이 한 번 렌더된 직후, 검증기가 다음을 수행합니다.

1. BeautifulSoup으로 HTML을 파싱.
2. `<script>`, `<style>`, `<svg>`, `data-noverify="true"` 영역은 검증 대상에서 제거 (Plotly 차트 SVG의 좌표·축 라벨 같은 false positive 차단).
3. 가시 텍스트 안의 모든 정수·소수·퍼센트 토큰을 추출.
4. 같은 빌드의 raw JSON 모두 합쳐 만든 multiset과 ±0.1% 또는 ±0.5 절대 허용 범위로 대조.
5. 결과(`checked` / `matched` / `unmatched`)를 HTML 하단 배지로 표시.

unmatched 비율이 5%를 넘으면 배지가 빨간색(`fail`)이 됩니다. 빌드는 실패하지 않지만, **눈으로 즉시 보입니다**. "검증 안 된 숫자가 절반인데 그래도 페이지를 띄운다" 같은 침묵을 시스템이 허락하지 않는 셈입니다.

### 3.3 Claim-level citation 검증 (`validators/citations.py`) — Phase 2의 핵심

Phase 2에서 LLM(즉, Claude Code 세션 자체)이 작성하는 6개의 자연어 슬롯이 추가됐습니다. 자연어를 들이는 순간 환각의 문이 다시 열립니다. 그래서 **모든 numeric claim**은 다음과 같이 wrap돼야 합니다.

```html
RSI(14) <span data-cite="329180_enriched.json:data.signals.rsi:61.2">61.2</span> 로 중립권에 머물지만 …
```

검증기는 슬롯 안의 모든 숫자 토큰을 훑어, 각각이

- (a) `data-cite` 속성으로 wrap돼 있는가 (의무 위반 = `uncited`)
- (b) 지정된 `file:json-path:value`가 raw 디렉토리의 실제 파일에서 따라가지는가 (불일치 = `mismatched`)

를 따집니다. 0~31 정수(일자·기간), 1900~2100 정수(연도), RSI 임계 50/70/30 같은 표준 상수는 면제. 결과는 다시 페이지 하단 두 번째 배지로 표시됩니다.

여기서 매우 중요한 결정이 하나 있습니다. **어떤 Python 코드도 OpenAI/Anthropic/Google의 LLM SDK를 자동 호출하지 않습니다.** 자연어 슬롯을 작성하는 주체는 *Claude Code 세션(즉, AI 어시스턴트 자체)*이고, 결과물은 `data/llm/{ticker}/{날짜}.json` 사이드카 파일로 디스크에 저장됩니다. 빌드 중인 main.py는 그 사이드카가 있으면 inject하고 없으면 룰 기반 fallback을 그대로 둡니다.

```json
{
  "ticker": "329180",
  "as_of": "2026-05-08",
  "slots": {
    "brief": {
      "raw_text": "5월 8일 종가 658,000원, 전일 대비 -5.05% 큰 폭 조정 …",
      "citations": [
        {"token": "658,000", "file": "329180_enriched.json", "path": "data.header.price_now", "value": 658000},
        {"token": "-5.05%",  "file": "329180_enriched.json", "path": "data.header.change_pct", "value": -5.05}
      ]
    },
    ...
  }
}
```

왜 이렇게 했는가? 다음 §4.2에서 설명합니다.

## 4. 기술 아키텍처 결정 — 왜 이 선택을 했나

설계는 결정의 연속입니다. 이 프로젝트에는 다섯 개의 의식적인 trade-off가 있고, 각각이 AI 리터러시 관점에서 가르침을 줍니다.

### 4.1 정적 HTML vs 인터랙티브 대시보드 (Streamlit/Dash)

**선택**: 정적 HTML(서버 없이 GitHub Pages 정적 호스팅).
**왜**: 운영 부담 최소화. Streamlit/Dash는 Python 프로세스가 항상 떠 있어야 하고, 매시간 자동화·공개 호스팅이 어렵습니다. 정적 HTML이라면 Plotly 차트조차 *서버 사이드에서 한 번* 렌더해 div 문자열로 박아두기 때문에, 사용자 브라우저는 단순한 HTML 한 장을 받습니다.
**비용**: 인터랙티브 필터링·드릴다운 불가. 받아들임.

### 4.2 LLM SDK 자동 호출 vs Claude Code 세션 직접 작성

**선택**: 자동 호출 금지. AI 어시스턴트가 직접 사이드카 JSON을 작성한다.
**왜**:

- 자동 호출하면 매 빌드마다 **API 비용이 발생**. 매시간 빌드 × 다수 종목 = 무시할 수 없는 OpEx.
- LLM 응답이 **그때그때 다르므로 재현성이 깨진다**. 같은 raw 데이터에 대해 동일 코멘트가 보장되지 않음.
- 사용자가 **코멘트를 보고 검토·교정**하는 사이클이 자연스럽게 끼어든다. AI가 자동으로 push해버리는 시스템보다 안전.
- **새 SDK 의존성이 늘지 않는다.** `requirements.txt`가 12개로 가볍게 유지됩니다.

**비용**: 코멘트가 자동 갱신되지 않음. 새 종목·날짜에 대해 사용자가 명시적으로 `/report-stock 329180` 슬래시 커맨드를 호출해야 함. 받아들임 — 오히려 *의도적 작성*이 환각 방지에 부합.

### 4.3 MCP + pykrx fallback 이중화

**선택**: 1차 소스는 `korea-stock-mcp`(Model Context Protocol 기반의 한국 주식 도구), 2차는 `pykrx` 라이브러리.
**왜**:

- MCP는 미래 표준이지만 한국 IP 의존성·도구명 변동 같은 운영 리스크가 있음.
- pykrx는 단단하지만 모든 도메인을 커버하지 못함.
- 둘 다 두면 **한쪽이 장애여도 빌드가 끝난다**.

```python
def _safe_fetch_price(ticker, fromdate, todate):
    try:
        return pykrx_price.fetch_ohlcv(ticker, fromdate, todate)
    except Exception as exc:
        logger.warning("%s 시세 fetch 실패: %s", ticker, exc)
        return None  # noop — 하위 분석은 빈 데이터로 graceful degrade
```

**비용**: 두 코드 경로를 유지해야 함. 받아들임.

### 4.4 로컬 Windows 작업 스케줄러 vs GitHub Actions cron

**선택**: 로컬 PC의 작업 스케줄러로 매시간 빌드, 결과 HTML만 GitHub에 push.
**왜**: pykrx가 `data.krx.co.kr`에 로그인하는데, 이 사이트는 **한국 IP에서만 안정적으로** 인증을 처리합니다. GitHub Actions의 미국 IP에서는 차단당해 빌드가 깨졌습니다. 클라우드 cron의 매력보다 안정성이 컸습니다.
**비용**: 사용자 PC가 켜져 있어야 함. 받아들임 — 어차피 본업이 PC 앞.

### 4.5 정규식 fallback 슬롯 + LLM 사이드카 inject

**선택**: 모든 자연어 슬롯에 대해 룰 기반 자동 생성 문장을 항상 준비. LLM 사이드카가 있으면 덮어쓰고, 없으면 그대로 둠.
**왜**: AI 코멘트가 없는 종목·날짜라도 **페이지가 무너지지 않는다**. "AI 의존"과 "AI 없이도 돌아감" 사이에서 후자를 기본값으로.
**비용**: 룰 기반 문장 작성 코드를 유지해야 함. 받아들임.

이 다섯 결정에서 일관된 철학이 보입니다. **재현성과 견고성이 새로움과 자동화보다 우선합니다.** AI 리터러시 관점에서 핵심은: AI가 만든 코드를 받아들일지 말지를 결정하는 권한이 *시스템 설계자에게* 있어야 한다는 것입니다. 자동 호출은 그 권한을 LLM에 양도하는 행위입니다.

## 5. Claude Code와 협업한 과정

### 5.1 두 단계로 나눈 이유

처음부터 LLM 코멘트까지 다 만들려고 했다면, 결정론 코어와 LLM 슬롯의 책임 경계가 흐려졌을 겁니다. 그래서 의식적으로 두 단계로 잘랐습니다.

- **Phase 1 (결정론 코어)**: LLM 미사용. 모든 슬롯은 룰 기반. 환각 방지 안전장치 1·2 (메타 트리플 + 숫자 대조)만 구현. 한 세션에서 마무리.
- **Phase 2 (LLM 코멘트 + claim-level citation)**: 슬래시 커맨드 `/report-stock` 도입. AI가 사이드카 작성. 안전장치 3 추가. 다른 세션에서 진행.

이 분리는 **한 세션이 너무 길어져 컨텍스트가 흐려지는 사고**를 막아주는 동시에, 각 단계의 산출물을 구체적으로 검증할 수 있게 해줬습니다.

### 5.2 `CLAUDE.md`와 `HANDOFF.md` — AI를 위한 두 통의 편지

세션이 끝나면 다음 세션의 AI는 **아무것도 모릅니다**. 그래서 다음 두 문서를 레포 루트에 두고 매 세션 시작 시 AI가 먼저 읽도록 강제합니다.

- **`CLAUDE.md`** — *영속적 운영 규칙*. "0. 가장 중요한 원칙"부터 "11. 변경 시 함께 갱신해야 하는 문서"까지. 디렉토리 매핑, 모듈 의존성 규칙, 디자인 토큰, 자주 묻는 질문 등 *바뀌지 않는* 규약. 새 의존성·새 디자인 토큰을 추가할 때 함께 갱신.
- **`HANDOFF.md`** — *시점별 인계*. "현재 어디까지 됐고 다음에 뭘 할지". `2026-05-08 Phase 1 완료 시점`처럼 날짜와 단계가 박혀 있고, "§5 즉시 확인이 필요한 항목"에 다음 세션의 첫 작업이 명시.

이 두 문서는 **사람이 읽기 위한 문서가 아니라 AI 에이전트가 읽기 위한 문서**입니다. 형식은 사람이 읽어도 좋지만, 톤은 명령형입니다 — "수정 시 이 매핑 유지", "변경·삭제 금지", "위반 시 사용자에게 확인 요청".

이 패턴은 AI 협업 일반에 응용 가능합니다. 어떤 시스템이든 두 통의 편지를 써두면 세션 간 단절을 줄일 수 있습니다.

### 5.3 슬래시 커맨드 `/report-stock`

`.claude/commands/report-stock.md` 파일은 단순한 마크다운이 아니라 **재사용 가능한 작업 절차서**입니다. 사용자가 Claude Code에서 `/report-stock 329180`를 입력하면 다음 7단계가 자동으로 진행됩니다.

1. `python -m src.main 329180` 실행 → raw 갱신
2. `data/raw/2026-05-08/329180_*.json` 모두 읽기
3. 6개 슬롯 자연어 작성 (한국어, 사실 기반, 매집/매도 시그널 포함)
4. 각 numeric token에 `{token, file, path, value}` citation 부착
5. `data/llm/329180/2026-05-08.json` 사이드카 저장
6. `python -m src.main 329180` 재빌드 → 두 검증 배지 확인
7. 사용자에게 HTML 경로·배지 상태·사이드카 경로 보고

여기서 AI 리터러시 관점의 통찰: **AI에게 "잘 분석해 줘"라고 부탁하지 않는다.** AI가 따라야 할 명시적 절차서를 마크다운으로 작성하고, 모든 단계에 검증 단계를 끼워넣었습니다. AI는 자유 작가가 아니라 **체크리스트를 따르는 분석가**로 동작합니다.

### 5.4 한 세션의 실제 흐름

전형적인 작업 세션은 다음과 같습니다.

1. 사용자: `HANDOFF.md §5 읽고 다음 작업 시작.`
2. AI: 영향받는 파일들을 `view`로 모두 읽음. 추측으로 수정 금지.
3. AI가 변경 계획 제시 → 사용자 승인.
4. AI가 코드 수정 + `python test_render.py`로 더미 데이터 smoke test.
5. 사용자가 실 데이터로 검증 (`python -m src.main <ticker>`).
6. 두 배지 확인. 안 맞으면 다시 §3 단계로.
7. 세션 끝나기 전 AI가 `HANDOFF.md` 갱신, 다음 세션의 첫 작업을 §5에 기록.

이 흐름의 핵심은 **검증 가능한 산출물을 매 단계 만든다**는 것입니다. "잘 됐어?"라는 모호한 질문이 아니라 "검증 배지가 pass인가?" "test_render가 통과했나?"라는 질문에 답할 수 있어야 진행합니다.

## 6. API 공포증이 어떻게 풀렸나

이 프로젝트가 의도하지 않은 가치 중 하나는, 외부 API 다루기에 대한 두려움이 단계적으로 해소된 것입니다. 일반화하면 **세 가지 안전망**이 함께 깔리면 API 공포증이 풀립니다.

### 6.1 키 없이 시작하기

처음에는 어떤 API 키도 받지 않은 상태에서 `python -m src.main 005930`이 일단 돌아가야 합니다. 이를 위해 `pykrx` 라이브러리(키 불필요)를 1차 fallback으로 두었습니다. 사용자는 *결과를 한 번 본 다음에* DART나 KRX 키 신청 여부를 결정할 수 있습니다. 거꾸로 "키부터 받으세요"라는 시스템은 진입 장벽이 너무 높습니다.

### 6.2 Graceful degrade

키가 없어도 *그 부분만 비어 있는 채로* 빌드가 끝납니다. main.py 곳곳에 다음 패턴이 있습니다.

```python
def _safe_fetch_disclosures(ticker, fromdate, todate):
    if not os.environ.get("DART_API_KEY"):
        logger.info("DART_API_KEY 미설정 — 공시 noop")
        return {
            "data": [],
            "source": "noop:disclosure",
            "tool_args": {"ticker": ticker, ...},
            "fetched_at": _now_iso_utc(),
        }
    ...
```

**노련한 운영 코드는 "에러를 던지지 않고, 빈 결과를 메타 트리플 형식 그대로 반환"합니다.** 하위 분석기는 빈 리스트를 받아서 빈 차트를 만들고, HTML은 "공시 데이터 없음"이라고 표시합니다. 페이지가 무너지지 않습니다. 즉, **부분적인 실패가 전체 실패가 되지 않는다**는 안전감.

### 6.3 실패해도 빌드는 끝낸다

검증 배지가 fail이어도 빌드가 끝납니다. 검증 결과는 *정보로* 표시되지, *결과를 차단하지* 않습니다. 이것이 사용자가 천천히 단계별로 개선할 수 있는 여유를 줍니다.

이 세 가지를 종합하면 사용자에게 다음과 같은 메시지가 전달됩니다.

> "키 없이 일단 돌려봐. 마음에 들면 DART 키 받아서 공시도 채워봐. 아직 검증 배지가 fail이어도 괜찮아 — 어디가 문제인지만 보면 되니까."

이것이 API 공포증을 해체하는 핵심 동학입니다. **"한 번에 완벽하게"가 아니라 "일단 돌고 나서 점진적으로"**.

## 7. AI 리터러시 관점 — 이 프로젝트가 보여주는 5가지 교훈

### 7.1 AI에게 자유 작문을 시키지 마라 — 절차서를 줘라

`/report-stock` 슬래시 커맨드는 35줄의 명시적 절차서입니다. AI는 "분석을 잘 하는" 것이 아니라 "절차를 정확히 따르는" 역할을 합니다. 결과의 일관성·재현성이 올라갑니다.

### 7.2 출력의 모든 숫자에 출처를 강제하라

`<span data-cite="file:json-path:value">` 패턴은 단순히 검증을 위한 것이 아니라, **AI가 생각하는 방식을 바꿉니다**. AI는 "그럴듯한 숫자를 자신감 있게" 쓰는 대신 "raw 파일에서 따라가지는 path를 먼저 찾고 그 path의 value를 인용"합니다. 출처 의무가 환각의 동력 자체를 차단하는 셈입니다.

### 7.3 LLM 호출을 자동화하지 말고 의도적으로 하라

LLM SDK 자동 호출 금지 결정은 비용 문제뿐 아니라 **재현성·검토 가능성** 문제이기도 합니다. 사용자가 명시적으로 "이 종목 코멘트 작성"을 트리거할 때만 LLM이 동작합니다. AI를 시스템의 *심장*이 아니라 *주문에 응답하는 도구*로 두는 것이 AI 리터러시의 핵심입니다.

### 7.4 두 통의 편지(`CLAUDE.md` + `HANDOFF.md`)를 써라

영속 규칙과 시점 인계를 분리해 적어두면, 다른 세션·다른 사람·미래의 자기 자신과 협업이 가능해집니다. AI 시대의 문서 작성은 사람만이 아니라 **AI 에이전트의 사용 설명서**이기도 합니다.

### 7.5 검증을 시스템에 내장하라 — 배지로 보이게 하라

페이지 하단 두 배지(`numbers` / `citations`)는 단순한 디버깅 도구가 아니라 **사용자에게 시스템의 신뢰도를 즉각 노출**하는 장치입니다. "신뢰하라"고 말하지 않고 "여기 검증 결과를 보라"고 말하는 시스템이 진짜 신뢰를 얻습니다.

## 8. 한계와 다음 단계

이 시스템은 의도적으로 작게 유지되어 있고, 그래서 다음과 같은 한계가 있습니다.

- **종목당 1페이지**. 그룹 종합·포트폴리오 뷰 없음. 필요해지면 인덱스 페이지 확장.
- **장중 실시간 갱신 없음**. 매시간 단위. 더 짧은 주기는 cron 빈도를 올리거나 webhook 기반으로 전환 필요.
- **TP(목표주가) 컨센서스 미수집**. 주요 무료 데이터 소스가 robots.txt에서 스크래핑을 disallow. 유료 API(FnGuide 등) 키를 확보해야 활성화.
- **Phase 3 옵션** (선택): 이벤트 스터디(수주공시 ±5일 CAR), 알림(Slack/이메일), 백테스팅 백엔드.

이 모든 확장은 §3 환각 방지 메커니즘을 깨지 않는 선에서만 진행합니다. 즉, **새 데이터 소스가 들어오면 메타 트리플 wrapping이 강제**되고, **AI가 작성한 새 코멘트는 모두 claim-level citation 의무**입니다.

## 9. 마치며 — AI를 도구로 두는 법

이 프로젝트는 결국 *AI를 어떻게 길들일 것인가*에 대한 한 가지 답입니다. 답의 핵심은 두 가지입니다.

1. **AI에게 자유를 주는 만큼, 검증을 끼워넣는다.** 자유는 환각의 자유이기도 합니다. 검증은 그 자유를 의미 있게 만드는 제약입니다.
2. **AI는 시스템의 심장이 아니라 도구다.** 자동 호출은 AI를 심장 자리에 앉히는 행위입니다. 슬래시 커맨드 + 사이드카 + 검증 배지 패턴은 AI를 *주문에 응답하는 분석가* 자리로 되돌립니다.

AI 리터러시는 프롬프트를 잘 쓰는 능력이 아니라, **AI가 만든 결과를 받아들일지 말지를 시스템 차원에서 결정할 수 있는 능력**입니다. 이 프로젝트의 코드 한 줄 한 줄에 그 능력의 작은 조각들이 박혀 있습니다.
